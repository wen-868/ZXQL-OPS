## 1. 强制统一的标准（运营系统必须遵守）

### 1.1 响应信封 `{ code, msg, data, traceId }`
- 成功：`code: "0"`，`data` 为业务数据（可为 `null`）。
- 失败：业务异常 `throw new AppError(...)`，由全局异常过滤器统一包装为 `{ code, msg, data:null, traceId }`，**不**在业务层手工拼响应。
- `traceId`：一次请求**唯一且贯穿全链路**（见 §3.1）。

### 1.2 错误以「字符串错误码」表达
- 管理系统主系统 `app-error.ts` 用数字 `statusCode` + 自由文本 `message`，**无集中错误码表**。
- **统一决策**：运营系统采用 `shared/error-code.ts` 的**字符串错误码表**（如 `TENANT_REQUIRED`、`INVALID_PARAM`、`BIZ_*`），优于主系统写法，作为运营系统规范。客户端契约稳定、可 i18n、可检索。
- 过滤器把字符串错误码映射为 HTTP 状态（4xx/5xx）。

### 1.3 配置集中化
- 所有环境变量集中 `env.ts`，复用管理系统同名变量：`DB_*`、`REDIS_*`、`JWT_SECRET`、`CSRF_SECRET`、`LOG_LEVEL`、`FEISHU_*`。
- 运营专属变量加 `OPS_` 前缀（如 `OPS_OLLAMA_HOST`）。
- `JWT_SECRET` 缺失即启动失败（对齐管理系统必填约束）。

### 1.4 多租户隔离
- 实体基类带 `tenantId` 列；请求头解析租户进 `TenantContext`（AsyncLocalStorage）。
- 服务层读取租户用 `TenantContext.requireTenantId()`，缺失即抛 `TENANT_REQUIRED`。
- 缓存键统一前缀 `tenant:{tenantId}:*`（对齐管理系统 `CacheKeys` 约定）。

### 1.5 分页标准
- 列表请求：`PaginationQueryDto`（`page`、`pageSize`）。
- 响应：`{ list, total, page, pageSize }`（字段名 `list`，**非** `records`）。
- 翻页越界由 `buildPage` 兜底。

### 1.6 日志 + 飞书告警
- 使用 pino；5xx 业务异常经飞书 webhook 告警（复用 `FEISHU_ALERT_WEBHOOK_URL`）。
- 日志必须带 `traceId`，按请求聚合。

### 1.7 代码风格（来自 ai-base）
- ESLint flat config：`typescript-eslint` 推荐 + `typed`/`typeChecked` + prettier、import 排序。
- Prettier：`singleQuote: true`、`semi: true`、`trailingComma: "all"`、`printWidth: 100`、`tabWidth: 2`。
- tsconfig：`strict: true`、`experimentalDecorators`、`emitDecoratorMetadata`、`target ES2022`、`moduleResolution bundler`。

## 2. 与管理系统存在分歧的点（已逐项拍板）

| 点 | 管理系统现状 | 运营系统决策 | 结论 |
|---|---|---|---|
| **traceId 生成** | 主系统 `ok()`/`fail()` 内部 `uuid()` 每次调用随机，同请求错误/响应对不上 | `TenantMiddleware` 一次请求生成 1 个 traceId（`x-trace-id` 可透传），interceptor/filter/`traceLogger` 共用 | **运营系统写法更优**，作为统一标准 |
| **响应字段名** | 主系统用 `msg`；ai-base 内部用 `message` | 统一 `msg`（对齐主系统） | 用 `msg` |
| **错误表达** | 数字 statusCode + 自由文本，无码表 | 字符串错误码表 `error-code.ts` | **运营系统增强**，作为标准 |
| **Redis 形态** | 主系统 `config/redis.ts` 函数式（`cacheGet` 等） | `RedisService`（NestJS 可注入，get/setJson/del/exists/expire/incr） | 运营系统服务化更 NestJS 化；键命名沿用 `tenant:{id}:*` |
| **校验库** | 主系统 Express 用 zod | 运营系统 NestJS 用 `class-validator` | 按框架选用 |
| **ESLint 形态** | 主系统根 `.eslintrc.cjs`（legacy）；ai-base `eslint.config.mjs`（flat） | 运营系统当前 `.eslintrc.js`（legacy） | **建议升级为 ai-base 的 flat config**（见 §4 待办） |

## 3. 模块开发自检清单（每个业务模块 A~Z 落地前对照）

- [ ] `*.module/.service/.controller/.entity/.dto.ts` 命名规范
- [ ] 响应一律走 `ok()` / `throw new AppError('码')`，不手工拼 `{code,msg}`
- [ ] 错误用 `error-code.ts` 中的字符串码，不写裸字符串
- [ ] 列表接口用 `PaginationQueryDto` + `buildPage`，返回 `{list,total,page,pageSize}`
- [ ] 所有 DB 查询带 `tenantId` 过滤；服务层用 `requireTenantId()`
- [ ] 鉴权 `@UseGuards(JwtAuthGuard)` + `@CurrentUser()`；敏感操作三档 auth
- [ ] 缓存键 `tenant:{tenantId}:*`，注入 `RedisService`
- [ ] 日志用 `traceLogger(traceId)` 或带 `traceId` 字段
- [ ] DTO 用 `class-validator` 装饰器
- [ ] 通过 `npm run lint` 与 `npx tsc --noEmit`
