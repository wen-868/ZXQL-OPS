### P0-2 B 域 OAuth 接入【规划 B-core 阶段1 契约】

**问题**：规划要求 `POST /accounts/oauth/start` + `GET /accounts/oauth/callback`；实现仅有手工建账号（account.controller.ts），无任何授权流程。

**目标设计**（对齐 P 域已有抖音 OAuth 模式：error-code.ts 已有 `PUBLISH_DOUYIN_*` 系列 + publish 模块凭证存 account_env/account token）：
1. `POST /ops/accounts/oauth/start` — body: `{platform, redirectUri}`；返回 `{authorizeUrl, state}`；state 落库 `account_oauth_states`（新表，含 tenantId、expiresAt 10min、used 一次性）
2. `GET /ops/accounts/oauth/callback` — 校验 state（过期/复用 → 400）→ 换 token → 存 `ops_accounts.token/token_expires_at/refresh_token` + `account_envs` → 返回结果页/JSON
3. 平台适配：`src/integration/oauth/` 下 `platform-oauth.adapter.ts` 接口 + douyin 适配器（复用 publish 模块已验证的凭证换取逻辑，避免两套）
4. 落地账号时触发 B 矩阵健康评估（与 account.service 既有 anti-associate 逻辑衔接）

**改动清单**：
- 新文件：`src/modules/account/oauth/`（controller 路由挂到 AccountController 或独立 OAuthController；adapter；dto/oauth-start.dto.ts）
- 新迁移 `024_account_oauth.sql`：`account_oauth_states` 表
- `error-code.ts` 新增：`OAUTH_STATE_INVALID(400)`、`OAUTH_STATE_EXPIRED(400)`、`OAUTH_PLATFORM_UNSUPPORTED(400)`
- `account.service.ts`：oauth 完成回调里复用 create/refresh 链路
- 前端：`src/api/account.ts` 加 `oauthStart/oauthCallback`；账号页「添加账号」弹窗出 authorizeUrl 跳转

**验收**：start 返回 authorizeUrl；模拟回调（无真实抖音凭据时走 stub 适配器返回 mock code）能落账号；state 一次性校验生效（同 state 二次回调 → OAUTH_STATE_INVALID）。

**影响面**：I/K/U 多账号分发受益（账号有了 OAuth 凭证才能真发）。

### P0-3 读期租户隔离兜底

**问题**：写期三层防护完整（tenant.subscriber.ts + TenantContext + beforeUpdate 抛 `TENANT_MISMATCH`），但**读期无统一兜底**——全部依赖各 service 手写 `where({tenantId})`；TenantGuard 不存在，新模块漏一处即跨租户泄漏。且 `TENANT_MISMATCH` 未在 error-code.ts 登记（AppError 兜底为 500 并误触发飞书告警，tenant.subscriber.ts:32）。

**方案（推荐两步走）**：
1. **立即**：`error-code.ts` 登记 `TENANT_MISMATCH: { message: '禁止跨租户操作', httpStatus: 403 }`；`app-error.ts` 确认允许传递 ERROR_CODES 外 key（已有兜底逻辑），一处改动解决 500 误报
2. **兜底**：新增 `src/tenant/base.repository.ts`（泛型 Repository<T> 子类）：
   - `find/findOne/findAndCount/query 包装`：有 TenantContext 时自动向 where 追加 `tenantId`
   - `findOneBy`（接受条件对象）同样处理
   - 业务模块按需切换 `@InjectRepository` → `@InjectRepository(Entity, CustomRepo)`（TypeORM 支持 `@EntityRepository` 已废弃，用 `TypeOrmModule.forFeature([Entity, TenantBaseRepository])` 传入 dataSource 方式）
   - 迁移成本：32 模块逐个换注入 + 明确「不需要租户过滤的查询（如系统技能目录）显式传 tenantId: null 跳过」语义

**备选（不推荐）**：全局 interceptor 扫描 SQL 字符串——脆弱且误伤 JOIN/子查询，放弃。

**验收**：单测覆盖——有 TenantContext 时 find 自动带 tenantId；显式 tenantId: null 时不注入；跨租户 update 返回 403 而非 500。

### P0-4 PII 滤除补齐六类

**问题**：intel.service.ts:26-33 仅 phone/geo/imei 三类；规划 §13 要求六类（phone/geo/imei/**id_card/precise_location/individual_profile**）一律剥离 + 日志 + 越权写入拦截记录（P 可读）。

**改动清单**：
- `intel.service.ts` PII_PATTERNS 补：
  - `id_card`：`/\b\d{17}[\dXx]\b/g`（15 位旧证 `\b\d{15}\b` 与 imei 冲突 → 用上下文区分：身份证前缀与日期规则）
  - `precise_location`：GPS 级 `/\b\d{2}\.\d{4,},\s?\d{2,3}\.\d{4,}\b/g`（经纬度，区别于现有城市名 geo）
  - `individual_profile`：`(出生于|生日[:：]?\d{4}年|身高|体重|家庭住址|身份证号[:：]?|电话[:：]?)` 关键词组
- 剥离日志：复用/扩展现有清洗日志（`ops_collect_tasks` 或新增审计表），记录命中类型计数，P 域合规日志页面可读
- 单测：intel.service.spec.ts 补三类新模式用例

**验收**：六类样本串全部被剥离为 `[已脱敏]`；命中计数可查。
