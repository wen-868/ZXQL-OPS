# 智享全链统一管理后台与数据互通规则方案

> 版本:v1.1 · 日期:2026-08-10 · 状态:方案评审稿(已按运营系统现有对接代码修订)
> 适用对象:管理系统(ZXQL-MS/wen-ssystem)+ 运营系统(ZXQL-OPS/zhixiang-ops-backend)

---

## 1. 现状与硬约束

### 1.1 管理系统(已部署服务器)

| 项 | 现状 |
|---|---|
| 后端 | Express,PM2 + Nginx,HTTPS,公网 `https://api.onepan.cn/api` |
| 管理后台 | Vue3 + Element Plus,`https://admin.onepan.cn`(另有 saas-admin 平台后台) |
| 数据库 | MySQL 8.4,库 `liquor_inventory`(62 张表),多租户 `tenant_id` |
| 用户 | `t_sys_user` + 角色(`t_sys_role`)+ 权限;登录 `POST /api/admin/auth/login` |
| JWT | HS256,issuer=`zhixiang-system`,audience=`zhixiang-client`,有效期 4h |
| JWT 载荷 | `{ id, username, realName, roles[], storeId, tenantId }` |
| CSRF | 登录返回 `csrfToken`,请求需带 CSRF 头 |
| 服务器 | 159.75.153.59;服务器无法访问本地运营系统(无内网互通) |

### 1.2 运营系统(本地打包模式)

| 项 | 现状 |
|---|---|
| 后端 | NestJS 11,`127.0.0.1:3100`,`dist/` 编译产物即打包形态 |
| 前端 | 静态 `ops-dashboard`(index.html + serve.js 代理,`127.0.0.1:8080`) |
| 数据库 | 本地 MariaDB,独立库 `zhixiang_ops`;Redis 本地 6379 |
| 用户 | `ops_users`(admin / t_dev / admin123),全局 JWT 守卫 |
| JWT | HS256,issuer=`zhixiang-ops`,audience=`zhixiang-ops-client`,有效期 7d |
| JWT 载荷 | `{ id, username, realName, role, tenantId, type }` |
| 租户 | 默认 `t_dev`;`.env` 中 `JWT_SECRET` 声明与管理系统同名变量对齐 |
| **已有对接设计** | `src/integration/` 规划 §7/§17:四类适配器 `ProductAdapter / OrderAdapter / CommissionAdapter / AuthAdapter`;`IntegrationService` 按 `OPS_INTEGRATION_MODE` 装配(`standalone` 默认,`connected` 接入管理系统);`modules/y` 已有 `syncOrders`(双源 management/platform、幂等去重、库存联动)、`syncInventory` 接口 |

> **结论(读码核实)**:运营系统不是从零对接,而是按既定契约实现 connected 适配器。本方案所有对接动作都落在 `integration/adapters.ts` 契约与 `y` 模块同步接口上,不新造轮子。

### 1.3 硬约束(方案必须满足)

1. **服务器访问不到本地**:管理系统后端/网关无法反向代理到本地运营服务,数据互通只能走「浏览器侧聚合」或「运营侧主动调用公网 API」。
2. **两套 JWT 互不兼容**:issuer/audience 不同、载荷结构不同(`roles[]` vs `role`),即使 `JWT_SECRET` 相同也无法直接互验。
3. **数据库物理隔离**:服务器 MySQL 与本地 MariaDB 不同实例,禁止跨库直连,只能 API 层互通。
4. **运营系统本地打包**:运营侧产物必须可脱离开发环境、一键启动,不依赖服务器部署。

## 2. 总体架构

```
┌─────────────────────────────────────────────────────────────┐
│                    浏览器(运营电脑)                          │
│                                                             │
│   统一管理门户 http://127.0.0.1:8080(本地打包产物)           │
│   ┌────────────────────────────┬───────────────────────────┐ │
│   │ 管理系统菜单(iframe/API)    │ 运营系统菜单(本地 API)      │ │
│   │ → admin.onepan.cn          │ → 127.0.0.1:3100          │ │
│   └────────────────────────────┴───────────────────────────┘ │
└──────────────┬───────────────────────────────┬───────────────┘
               │  HTTPS(公网)                   │  HTTP(本地)
               ▼                                ▼
   ┌─────────────────────┐          ┌─────────────────────────┐
   │ 管理系统服务器        │          │ 本地运营系统              │
   │ api.onepan.cn        │          │ NestJS :3100            │
   │ admin.onepan.cn      │          │ MariaDB zhixiang_ops    │
   │ MySQL liquor_...     │          │ Redis :6379             │
   └─────────────────────┘          └─────────────────────────┘
```

### 2.1 原则

- **一个入口**:统一门户 = 运营系统本地打包产物(唯一新增的聚合壳)。
- **一套账号**:登录统一走管理系统账号体系,运营系统通过 `AuthAdapter` 实现的 SSO 信任管理系统 JWT。
- **两类数据流**:
  - 浏览器直连(管理系统公网 API、运营本地 API);
  - 运营后端经 `ProductAdapter/OrderAdapter` 主动拉取管理系统公网 API(主数据镜像,可离线)。
- **四个不许**:
  1. 不许服务器反向代理到本地;
  2. 不许跨库直连(禁止运营库访问管理系统库,反之亦然);
  3. 不许复制密码(账号归属管理系统,运营只存映射与角色);
  4. 不许让用户手动维护两套登录。

### 2.2 双模式运行规则(核心)

| 模式 | `OPS_INTEGRATION_MODE` | 行为 | 数据 |
|---|---|---|---|
| 独立模式(默认) | `standalone` | 运营系统完全自营:本地账号登录、订单走 platform 源、四类适配器为 `NotImplementedAdapter`(调用即 `NOT_IMPLEMENTED`) | 全量存本地 `zhixiang_ops`,不依赖管理系统 |
| 对接模式 | `connected` | 登录走管理系统 SSO;订单默认 `source=management`;商品/库存/订单由适配器从管理系统拉取;运营业务(直播/短视频/达人/投放)仍本地运行 | 主数据 4 类镜像到本地,运营业务数据本地 |

- **切换规则**:改 `.env` 的 `OPS_INTEGRATION_MODE` 后重启后端即生效;切换不影响已入库数据(镜像表保留,standalone 下不再刷新);
- **降级规则**:connected 模式下管理系统不可达时,运营核心功能(本地业务)继续可用,仅同步/SSO 相关接口报「管理系统不可达」,不允许静默写脏数据;
- **升级规则**:standalone → connected 为可逆操作;connected → standalone 需人工确认(防止误以为已同步)。

## 3. 统一管理后台规则

### 3.1 门户形态

统一门户采用**运营本地静态门户 + 双域聚合**:

- 门户静态资源(HTML/JS/CSS)属于运营打包产物,启动 `node serve.js` 即得 `http://127.0.0.1:8080`。
- 左侧导航两级:
  - 「管理系统」:跳转/嵌入 `https://admin.onepan.cn`(服务器后台,完整功能);
  - 「运营系统」:运营看板/运营管理(本地 3100);
  - 「统一工作台」:聚合仪表盘(可选,一期不做)。
- iframe 嵌入规则:
  - 管理系统后台使用 iframe 嵌入时,必须由门户代发登录态(见第 4 节 SSO);
  - iframe 内容禁止用 `document.domain` 放开跨域,统一用 postMessage 传递「已登录」事件;
  - 管理系统后台被 iframe 嵌入需在服务器 Nginx 配置 `X-Frame-Options SAMEORIGIN` + `frame-ancestors` 白名单放行本地门户。

### 3.2 菜单与权限映射规则

| 管理系统角色 | 运营系统角色映射 | 门户可见菜单 |
|---|---|---|
| SUPER_ADMIN | super_admin | 全部(含运营全部模块) |
| OPERATION_ADMIN | ops_admin | 运营全部 + 管理系统经营类 |
| FINANCE_ADMIN / WAREHOUSE_ADMIN | ops_viewer(只读) | 运营只读 |
| 其他(门店/收银) | 无 | 仅管理系统原有菜单 |

- 角色映射表存运营库 `ops_role_bind`(见 5.3),由门户启动时下发到前端;
- 前端只做菜单显隐,后端必须二次鉴权(运营后端校验 `role` + 模块权限)。

### 3.3 门户路由规则

- 门户路由前缀:`/ms/*`(管理系统)、`/ops/*`(运营系统)、`/login`(统一登录);
- 未登录访问任一前缀 → 重定向 `/login`;
- 登录后按角色默认落地:超级管理员 → `/ms`,运营管理员 → `/ops`;
- 会话过期(任一系统 401)→ 门户清空本地凭据并回 `/login`。

## 4. 统一认证(SSO)规则

### 4.1 登录流程(推荐:管理系统为主认证源)

```
门户 /login → 调 POST https://api.onepan.cn/api/admin/auth/login
            → 得管理系统 JWT(issuer=zhixiang-system)
            → 门户持该 JWT 调 POST http://127.0.0.1:3100/api/ops/auth/sso
            → 运营签发自有 JWT(issuer=zhixiang-ops)+ 返回运营用户/角色映射
门户存储:MS_TOKEN(管理系统)+ OPS_TOKEN(运营系统)+ 角色映射
```

### 4.2 运营系统 SSO 改造(必做)

SSO 落在既有 `AuthAdapter` 契约上,新增 `ConnectedAuthAdapter` 实现:

1. `verifyToken` 支持**双签发源**:
   - 自有 token:issuer=`zhixiang-ops`,audience=`zhixiang-ops-client`;
   - 管理系统 token(仅限 SSO 端点校验):issuer=`zhixiang-system`,audience=`zhixiang-client`;
2. 新增端点 `POST /api/ops/auth/sso`:
   - 入参:`Authorization: Bearer <管理系统JWT>` + `x-tenant-id`;
   - 校验管理系统 JWT(HS256 + 同 `JWT_SECRET` + issuer/audience);
   - 按 `username` 查 `ops_users`,不存在则自动建号(角色按 3.2 映射,`type='connected'`);
   - 签发运营 JWT 并返回 `{ token, user, roleBind }`;
3. `IntegrationService` 装配:`OPS_INTEGRATION_MODE=connected` 时用 `ConnectedAuthAdapter` 替换 `NotImplementedAdapter`;
4. `JWT_SECRET` 统一:服务器管理系统 `.env` 与本地运营 `.env` 必须配置**同一个** `JWT_SECRET`(部署时人工核对,不一致则 SSO 失败);
5. 载荷映射规则:

| 管理系统载荷 | 运营载荷 | 规则 |
|---|---|---|
| `roles[]` | `role` | 取映射表最高权限角色(3.2) |
| `tenantId` | `tenantId` | 经租户映射表转换(5.2) |
| `id` | `id` | 不直接复用,按 username 绑定运营用户 |
| `type` | `type='connected'` | 标记来自管理系统,禁止降级为 standalone 提权 |

### 4.3 运营后端双 token 校验规则

- 业务接口:只接受**运营自有 token**(issuer=`zhixiang-ops`);
- `POST /api/ops/auth/sso`:只接受管理系统 token;
- 其余来源一律 401;
- 守卫中禁止对任意 issuer 放行业务接口(防绕过)。

### 4.4 CSRF 规则

- 管理系统保留自身 CSRF(登录返回 `csrfToken`,写操作带头);
- 运营系统写接口(POST/PUT/PATCH/DELETE)增加 CSRF 校验:
  - 令牌:登录/SSO 时下发,存 `ops_csrf_token`;
  - 校验:请求头 `x-csrf-token` 必须匹配会话令牌;
  - 豁免:仅允许健康检查与只读接口。

## 5. 数据互通规则

### 5.1 互通边界

**同步范围固定为 4 类:商品、客户、库存、订单。** 除此之外的数据不做跨系统同步。

| 数据方向 | 通道 | 说明 |
|---|---|---|
| 商品/订单(→运营) | `ProductAdapter.getProductsByIds` / `OrderAdapter.listOrders` | connected 模式实现,服务账号凭证见 5.4 |
| 客户(→运营) | 新增 `ops_ms_customer` 镜像表 + 同步任务 | 管理系统客户为主,运营只读镜像 |
| 库存(→运营) | 复用 `y` 模块 `syncInventory` 接口 | 管理系统库存为真源,运营侧扣减结果回写由管理系统确认 |
| 管理系统 → 看运营数据(直播/短视频/达人/投放) | 浏览器直连本地 3100(门户聚合) | 服务器不反向代理 |
| 双向实时写 | 一期禁止跨系统直写 | 各自写本地,同步走 5.5 规则 |

### 5.2 租户映射表(运营库)

```sql
CREATE TABLE ops_tenant_bind (
  id BIGINT AUTO_INCREMENT PRIMARY KEY,
  ms_tenant_id VARCHAR(64) NOT NULL COMMENT '管理系统租户',
  ops_tenant_id VARCHAR(64) NOT NULL COMMENT '运营系统租户',
  status TINYINT NOT NULL DEFAULT 1,
  UNIQUE KEY uk_ms_tenant (ms_tenant_id),
  KEY idx_ops_tenant (ops_tenant_id)
) COMMENT='管理系统↔运营系统租户映射';
```

- 首启种子:`('default','t_dev')`、`('1','t_dev')` 等按实际填;
- 门户/运营请求统一以 `ops_tenant_id` 入库,SSO 时按映射转换;
- 映射变更需同步刷新已签发的运营 token(短时效 + 变更后强制重登)。

### 5.3 角色映射表(运营库)

```sql
CREATE TABLE ops_role_bind (
  id BIGINT AUTO_INCREMENT PRIMARY KEY,
  ms_role VARCHAR(64) NOT NULL COMMENT '管理系统角色码',
  ops_role VARCHAR(64) NOT NULL COMMENT '运营角色',
  menu_scope VARCHAR(255) NOT NULL DEFAULT 'ops' COMMENT '菜单范围:ms/ops/all/readonly',
  UNIQUE KEY uk_ms_role (ms_role)
) COMMENT='管理系统→运营角色映射';
```

### 5.4 运营后端访问管理系统(服务凭证)

- 不使用用户 JWT,运营后端配置服务账号:
  - `OPS_MS_API_BASE=https://api.onepan.cn/api`
  - `OPS_MS_CLIENT_ID` / `OPS_MS_CLIENT_SECRET`(管理系统新增「服务账号」,权限最小化);
- 令牌:运营后端用 client 凭证调管理系统 `POST /auth/token`(需管理系统新增服务账号端点)换短时 access_token 缓存;
- 调用方在管理系统侧记录审计(`x-request-source=zhixiang-ops`)。
- 对接目标接口(管理系统已存在,复用 `/api/admin/*`):
  - 商品:`GET /api/admin/products`(分页+keyword)、`GET /api/admin/products/:spuId`
  - 客户:`GET /api/admin/members`、`GET /api/admin/customers`(按实际路由)
  - 库存:管理系统库存/库存预警接口(按 `stock-*.controller` 实际路由)
  - 订单:`GET /api/admin/orders`
- 适配器返回统一收敛为契约 DTO(`ProductDTO` 等),禁止业务模块直接依赖管理系统响应结构。

### 5.5 主数据同步规则(仅 4 类,运营侧镜像)

| 数据 | 同步方向 | 频率 | 策略 |
|---|---|---|---|
| 商品/SPU/SKU | 管理系统 → 运营 | 每 5 分钟增量 | 幂等 upsert,`updated_at` 游标 |
| 客户/门店 | 管理系统 → 运营 | 每 10 分钟 | 幂等 upsert |
| 库存 | 管理系统 → 运营 | 每 5 分钟 | 全量快照替换 |
| 订单 | 管理系统 → 运营 | 实时+每 5 分钟 | 按单号幂等,补漏重试 |

- 同步实现:运营后端 `@nestjs/schedule` 定时任务(已引入),失败重试 3 次 + 飞书告警;
- 同步状态表 `ops_sync_cursor`(数据源、游标、last_success_at、error);
- 一期以「管理系统 → 运营」单向为主,避免双写冲突。
- **独立运行保证**:`standalone` 模式下不启动同步任务、不调用适配器,运营系统全部功能可用;同步任务仅在 `connected` 模式装配。

### 5.6 数据一致性规则

- 跨系统主键:管理系统用 `ms_xxx_id` 外键引用,运营本地表加 `ms_id` 列,禁止混用自增 id;
- 删除:软删,运营镜像只置 `sync_deleted=1`,不物理删;
- 金额/库存:以管理系统为准,运营只读展示;
- 审计:所有跨系统读写在 `ops_audit_logs` 与管理系统审计双记录。

## 6. 本地打包与部署规则

### 6.1 打包产物清单

```
ops-release/
  backend/          # NestJS dist/ 编译产物 + node_modules(生产)
  frontend/         # 统一门户静态产物(index.html + assets)
  serve.js          # 静态托管 + /api 代理(已存在,按第 7 节加固)
  start.ps1         # 一键启动:MariaDB→Redis→backend→serve.js
  .env              # 生产配置(含 JWT_SECRET,与管理系统一致)
```

### 6.2 启动规则

- `start.ps1` 依次探测 3306/6379/3100/8080,缺失则启动(复用 `ops-trial.ps1` 逻辑);
- 后端必须以 `NODE_ENV=production` 启动,日志落盘 `logs/`;
- 前端门户指向:
  - 运营 API:同源代理 `http://127.0.0.1:3100`;
  - 管理系统 API:`VITE_MS_API_BASE=https://api.onepan.cn/api`(构建时注入);
- 端口固定:3100(后端)、8080(门户),冲突时启动脚本报错退出,禁止静默换端口。

### 6.3 版本规则

- 运营打包产物带版本号 `package.json version` + 构建时间戳;
- 升级 = 替换 `ops-release` 目录 + 重启,数据库迁移用 `migrations/` 顺序执行;
- 回滚:保留上一版目录,`start.ps1 -Rollback`。

## 7. 安全规则

1. **密钥**:本地运营 `.env` 的 `JWT_SECRET`、`CSRF_SECRET` 与服务器管理系统保持一致;严禁提交到 Git;
2. **签发隔离**:业务接口只认 `zhixiang-ops`;SSO 端点只认 `zhixiang-system`;双 issuer 同时校验 audience;
3. **服务凭证**:运营→管理系统一律走服务账号,不转发用户 JWT,密钥加密存储(可复用管理系统 `ENCRYPTION_KEY` 思路);
4. **CORS**:本地门户 origin 白名单,只允许 `http://127.0.0.1:8080` 与 `http://localhost:8080`;
5. **iframe 防护**:管理系统 Nginx 增加 `Content-Security-Policy: frame-ancestors 'self' http://127.0.0.1:8080`;门户禁止夹带第三方页面;
6. **传输**:本地也启用 HTTPS 可选(`OPS_HTTPS=1`,自签证书仅限内网);
7. **审计**:SSO 登录、跨系统读、同步任务、角色变更全部落审计日志;
8. **脱敏**:日志不打印 token/密码/密钥,统一 `***`。

## 8. 实施步骤与验收

| 阶段 | 内容 | 验收标准 |
|---|---|---|
| P0 | 统一 `JWT_SECRET` 核对;管理系统新增服务账号端点 | 双端密钥一致文档化;服务账号可换 token |
| P1 | 运营 SSO:实现 `ConnectedAuthAdapter`(`/api/ops/auth/sso` + 双 issuer 校验 + 用户/角色映射表) | 管理系统 JWT 可换运营 JWT;错误 issuer 被拒;standalone 不受影响 |
| P2 | 本地统一门户(导航 + 登录 + iframe 嵌入 + CSRF) | 单次登录可进两个系统;过期回登录页 |
| P3 | 主数据同步(商品/客户/库存/订单):实现 `ProductAdapter`/`OrderAdapter` connected 版 + 客户镜像表 + 同步任务 | 运营库与管理系统 4 类数据一致率 100%(抽样校验);standalone 下任务不启动 |
| P4 | 打包与一键启动;Nginx CSP 加固 | 全新机器按文档可 30 分钟起全栈 |
| P5 | 安全回归:401/403/CSRF/服务凭证/审计 | 越权用例全拦截 |

## 9. 风险与待确认项

1. **管理系统是否已有「服务账号/客户端凭证」机制**——没有则需在管理系统加最小端点(P0);
2. **管理系统 JWT 4h 时效**——门户需静默续期或引导重登,运营 SSO 令牌 7d 与管理系统 4h 不一致,建议运营令牌时效跟随管理系统(4h);
3. **管理系统服务器 Nginx 是否允许被 iframe 嵌入**——需运维配合放行 `frame-ancestors`;
4. **租户映射现状**——管理系统 `tenant_id` 实际值需要与运营 `t_dev` 的对应关系确认;
5. **运营系统 CSRF 尚无实现**——需评估是否为「一期必做」还是「先做 token 校验」;
6. **双向数据写**——一期仅管理系统→运营单向,双向写需二期评估。
7. **客户镜像落点**——运营系统当前无 `customer` 实体,客户同步落 `ops_ms_customer` 只读镜像表(本方案已按此设计),需确认运营哪些模块消费该镜像(如达人商单关联客户)。
